# M1.1 플레이테스트 체크리스트 (AC 15, F16 천장 게이지 + 성공 숙련)

> 상태: **사용자 플레이테스트 대기(pending user playtest). 블로커 아님.** 밸런스 게이트가 아니며, 기록은 `docs/design/m1.1-late-correction.md` §7 튜닝표의 입력으로만 쓴다.
> 수치는 시뮬레이션으로 검증하지 않았다. 스펙의 "Realistic 5~8시간"은 **추정이지 측정이 아니다.**

## 1. 준비
- [ ] 저장 초기화: 개발자 도구 콘솔에서 `localStorage.removeItem('sword-enhance-v2')` 후 새로고침, 또는 새 브라우저 프로필 사용
- [ ] `index.html`을 `file://`로 열거나 프리뷰 서버로 실행 (`test.html`은 강제 성공이라 **사용 금지**, 별도 저장 키)
- [ ] 평소처럼 플레이: 소모품(축복/보호권/모루 등)은 아껴 쓴다. 치트·콘솔 조작 금지
- [ ] 시간은 **접속해서 실제로 플레이한 시간**으로 잰다(탭을 닫아 둔 시간, 오프라인 보상 시간 제외)

## 2. 기록 항목
- 시작 일시 / 브라우저 / 실행 방식(file:// 또는 서버)
- +10, +15, +20 최초 도달 시각(**누적 플레이 시간**, 벽시계 아님)
- 단계별 소모품 사용량(축복, 보호권, 하락 방지, 확정 강화권, 모루 내구도)
- +15~+19 단계별 시도 수, 파괴 수
- 천장 확정 성공(`확정!`)을 본 횟수(단계별)
- 숙련 기록 획득 수(토스트 기준)와 기록 탭의 최종 숙련 값
- 인상 메모: 지루한 구간, 운이 나빴던 구간, 숙련·천장 체감 여부, UI 혼란

## 4. 판정 안내
- 합격/불합격 기준 없음(밸런스 게이트 아님). 총 시간이 대략 5~8시간 범위인지만 참고한다. 범위 밖이어도 실패가 아니라 튜닝 입력이다.
- 막히는 기능 버그(저장 손실, 게이지가 안 찬다, 확정인데 소모품이 줄어듦 등)는 별도 버그로 보고한다.

## 5. 증상 → 손잡이 (스펙 §7)
| 증상 | 손잡이 |
| --- | --- |
| +20까지 너무 오래 걸림 | `GAUGE_N`을 줄임(예 [3,4,5,6,8]) 또는 `MASTERY_STEP`+1 |
| Heavy가 너무 빠름 | `MASTERY_STEP`/`MASTERY_MAX` 감소 |
| +17~+19에서 숙련 체감이 없음 | +17~+19의 `MASTERY_STEP` 증가 |
| +20 대기가 여전히 지나치게 김 | `GAUGE_N=[2,3,4,5,6]` (+20 약 28%가 확정 성공, 과함 주의) |
| Light가 +20까지 못 감 | 이 방향을 벗어남: +10~+14에도 성공 기록(STEP 1~2, 최대 6%p) |
- 값은 `js/constants.js` 배열만 바꾼다. `MASTERY_REC_MAX`는 `ceil(MAX/STEP)`으로 다시 계산한다.
