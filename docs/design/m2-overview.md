> 상세 규칙은 각 문서: `m2-traits.md`(F14 특성 규칙, 시스템 기획 담당) · `m1-balance.md`(M1 수치 기준선) · `m1-storage.md`(저장 구조) · `m1-constants-index.md`(상수 총람) · `m1.1-late-correction.md`(F16 게이지·숙련, §8 환생 메모) · `m1-overview.md`(루프·자원) · `m2-achievements.md`(F12 업적·일일 과제, 배치 B) · `m2-events.md`(F13 시간 이벤트, 배치 B). 이 문서는 **M2 전체 순서, 4-0 골드 사용처 분석과 모든 가격식, 배치 A·B 저장 필드 표**를 소유한다(배치 B 필드의 규칙 본문은 위 두 문서). 수치는 기획 판단 + 기존 상수로 한 단순 산수이며 시뮬레이션으로 검증하지 않았다(플레이 테스트로 조정).

## B. 4-0 분석: 후반 골드는 어디서 오고 어디로 가는가

### B.1 전제
- 수동 사냥: 쿨다운 `HUNT_CD`=2.5초 → **연속 24회/분**. 실제 플레이어는 강화·관리 시간이 있어 연속으로 사냥하지 않는다 → **듀티 25~50%**(6~12회/분)를 현실 가정으로 쓴다.
- 자동·오프라인: `autoReward(l) = max(10, round(0.1×cost(l)))`, 수확 보너스 lv5(`UP_GOLD_STEP`×5 → ×1.5), 자동 간격 5초(속도 업그레이드 없음) → 접속 중 12회/분. 오프라인 8시간 = 5,760회 × `autoReward` × 1.5 × `OFFLINE_EFF`(0.25).
- 수입 기준 검은 `topLv`(≈ `S.best`). 아래 표의 l = 최고 단계.

### B.5 결론
1. **주 수입원은 수동 사냥**이다. 듀티 25%에서도 +15부터 자동(분당 25.8k)의 2.1배(54.9k), +17 3.0배, +20 5.2배다. +13에서는 듀티 25%에서 자동(10.7k)이 오히려 많고 50%에서 3배다 → "수동이 압도적으로 우세"는 약 +13~15부터다. 자동·오프라인은 누적량이 작다(오프라인 8h = 연속 사냥 6~20분 분량).
2. 판매(`sell`)·의뢰는 **덩어리**다. +17의 어려움 의뢰 1개(1.02M)는 연속 사냥 1.35분. 하지만 검 한 자루를 갈아 넣어야 해서 순수익은 작다.
3. **고정 지출 총합**(칸 확장 323k + 방치 업그레이드 505k + 모루 25k ≈ **0.85M**)은 +13에서 연속 사냥 약 13분(듀티 25%면 53분)이면 모두 충당된다. 강화 1회는 +15부터 사냥 1회(0.64회분)로 갚는다. 소모품은 가장 비싼 booster를 빼면 4,000G 이하다.
4. 따라서 **약 50만~100만G(약 +13)에서 기존 사용처가 모두 소진되거나 무시할 수준**이 된다 → 3-1 플레이 테스트 결과("약 50만G 이후 골드가 남아 소모품을 아낄 이유가 없음")와 일치한다. **기존 수입·가격은 바꾸지 않는다**(사용자 결정).

## C. 골드 사용처 설계 (팀장 결정, 산수 검증)

### C.0 규칙
- **규칙 0**: 사용처는 모두 **선택**이다. 성공 확률·게이지·숙련·`BONUS_CAP`에 아무 영향도 주지 않고, +20에 필수가 아니며, **스스로 본전을 뽑는 수입을 주지 않는다**. 따라서 `UP_MAX` 확장 안(자동 업그레이드 단계를 늘려 수입을 더 키우는 방식)은 기각한다.
- 가격 기준은 `huntReward(best)`(수입 단위). `cost(best)`는 +15 이상에서 사냥 1회보다 작아 단위가 될 수 없다(B.4).
- 반올림: 모든 가격은 `round100`(`TRAIT_PRICE_ROUND`=100).

### C.3 단계 기념비 (장식 수집)
- 보상은 **순수 장식**: 레벨별 영구 머리글/기록 배지 + 칭호 문구. 추가로 F12 업적이 "기념비 N개" 같은 카운터를 읽을 훅을 둔다(확정: 업적 `mon_1/2/3`(보유 1·4·8개)이 `monumentCount`를 읽고, `stats.sinkGold`는 `sink_1/2/3`(50만·1,000만·1억)에 쓰인다. `m2-achievements.md`).
- UI 위치(잠정): 기록 탭의 "기념비" 섹션. 8칸, 상태 = 잠김(best<L) / 구매 가능 / 보유.
- 규칙(`buyMonument(S, L)`): 인자 L은 정수 13..20.
| # | Given | When | Then |
| --- | --- | --- | --- |
| M1 | `S.best ≥ L`, `S.monuments[L-13]=0`, `S.gold ≥ monumentCost(L)` | `buyMonument(S, L)` | `{ok:true, price}`. 골드 −price, `monuments[L-13]=1`, `stats.sinkGold += price`, 확률 관련 값 불변 |
| M2 | `monuments[L-13]=1` | `buyMonument(S, L)` | `{ok:false, reason:'owned'}`, 골드 불변 |
| M3 | `S.best < L` | `buyMonument(S, L)` | `{ok:false, reason:'notReached'}`, 골드 불변 |
| M4 | `S.best ≥ L`, `S.gold < monumentCost(L)`, 미보유 | `buyMonument(S, L)` | `{ok:false, reason:'noGold'}`, 골드 불변 |
| M5 | L이 13..20 정수가 아님 | `buyMonument(S, L)` | `{ok:false, reason:'invalid'}`, 상태 불변 |
- 검사 순서: invalid → owned → notReached → noGold.

### C.4 "연속 사냥 분"과 "강화 시도 횟수" 환산
환산: 분 = 가격 ÷ (24×H), 시도 = 가격 ÷ cost(best). 가격이 모두 H의 배수라 **분은 best와 무관하게 같다**(H에 비례하므로).
| 사용처 | 연속 사냥 분 | best 13 시도 / best 15 / best 17 / best 20 |
| --- | --- | --- |
| 종류 변경 (80H) | 3.3분 | 35.9 / 51.2 / 72.9 / 123.9회 |
| 등급 1→2 (200H) | 8.3분 | 89.8 / 127.9 / 182.2 / 309.8회 |
| 등급 2→3 (500H) | 20.8분 | 224.5 / 319.8 / 455.5 / 774.5회 |
| 기념비(해당 단계 L = best, 150H) | 6.3분 | 67.3 / 95.9 / 136.6 / 232.3회 |
- **best 13**: 종류 변경 214k, 등급 1→2 535k, 등급 2→3 1.34M, 기념비 401k → **0.2M~1.3M**로 약 50만 G 더미와 맞는다.
- **이후에도 "비싸지만 도달 가능"**: 단일 사용처 3.3~20.8분(연속 사냥 기준, 듀티 25%면 13~83분), 기념비는 각 6.3분. 가장 비싼 등급 2→3(500H)도 한 번이다.
- **전부 사는 데 걸리는 시간**(한 검 특성 3종 + 해당 best까지의 기념비 전부, 1회씩): 
| best | 기념비 누적 | 특성 3종(780H) | 합계 | 연속 사냥 분 | 듀티 25% 시간 |
| --- | --- | --- | --- | --- | --- |
| 13 | 401k | 2.09M | 2.49M | 38.8분 | 2.6h |
| 15 | 2.52M | 7.14M | 9.66M | 44.0분 | 2.9h |
| 17 | 9.76M | 24.45M | 34.21M | 45.5분 | 3.0h |
| 20 | 64.32M | 154.80M | 219.12M | 46.0분 | 3.1h |
  (합계 연속 분 ≈ (기념비 누적 + 780H) ÷ 24H. 기념비 누적은 낮은 단계 기념비를 이전 best에서 이미 샀다고 보면 더 적다.) 최고 단계 기준 **몇 시간 안**에 끝난다. 단, 특성 종류 변경은 재굴림이라 여러 번 쓸 수 있는 반복 사용처이고, 반복 횟수는 자발적이다(규칙 0).
- **강화 골드 고갈 점검**: 사용처가 강화를 굶기는지는 "강화 1회 비용 ÷ 사용처 가격"으로 본다. 종류 변경 기준 best 13 2.8% · 15 1.95% · 17 1.37% · 19 0.96% · 20 0.81%, 등급 1→2는 best 15 0.78% 이하, 등급 2→3·기념비는 best 13부터 모두 2.2% 이하(기념비 best 13: 1.5%). 팀장 안의 "best≥15에서 1% 미만"은 **종류 변경에는 best 15~18에서 1.95~1.15%라 성립하지 않는다**(전 구간 2% 이하로 정정). 굶김 문제는 없다: 사용처를 사고 나서 다시 강화 1회를 하려면 사냥 0.45~1.6회만 필요하다(H ÷ cost, B.4).

### C.5 페이스 보호 (+20 속도 불변)
- 사용처와 기념비는 `chances()`·게이지·숙련·`BONUS_CAP`에 입력을 주지 않는다 → 같은 입력이면 성공·파괴 확률이 변하지 않는다(I-7 회귀).
- **페이스 보호의 근거는 "특성이 확률을 건드리지 않는다"는 것 하나다.** 특성은 첫 +5 도달 때 무료로 붙고(`m2-traits.md` §5) 수입 효과는 `topLv` 기준으로 바로 적용되므로, 특성 관리(best ≥ 13)와 달리 **+5~+12 골드 제한 구간도 영향을 받는다**. 효과 전체(`m2-traits.md` §3·§16): 수동 사냥 골드 최대 +30%, 자동·오프라인 골드 최대 +45%, 광석 최대 +60%, 상인은 그 검의 판매·납품 최대 ×1.3(감정 인장 ×1.3과 곱해 최대 ×1.69), 수집가 파편 최대 +50%, 대장장이 모루 내구도 최대 45% 절약. 종류별로 최댓값만 적용되고 합산되지 않는다.
- **초반 단축 폭 추정(산술만, 시뮬레이션 아님)**: 골드 제한 구간(+5~+12)의 수입은 대부분 수동 사냥이라 약탈자 +30%(전체 검의 1%에서만 나옴)가 최선의 경우 이 구간 시간을 최대 1 − 1/1.3 ≈ 23% 줄인다. 무작위 검의 기대 사냥 보너스는 0.20 × (0.70×10 + 0.25×20 + 0.05×30)% = 0.20 × 13.5% ≈ 2.7%라 보통은 3% 안팎, 약탈자 1등급이 붙어도 +10%(약 9%)다. 그 구간이 +20 전체 약 25분 중 수 분이므로 **최악의 경우에도 전체 단축은 1~2분 이하**(약 5% 이하), 일꾼·광부·상인은 이 구간에서 효과가 더 작거나 간접적이다. **플레이 테스트 항목**: +5~+12 구간 시간을 특성 유무로 비교해 기록한다. 기획 한계는 10%를 넘으면 `TRAITS` 값(약탈자)을 낮춘다.
- +13 이후 골드는 이미 남는다(B.5).
- 사용처 구매는 골드만 빼며 시간 단축 수단이 아니다. 즉 +20 약 25분(1,261회) 목표와 불운 40~50분은 그대로다.
- **배치 B 점검**: 업적·일일 골드 합계(업적 `131H` = 연속 사냥 5.5분 1회성, 일일 하루 `16H` = 0.67분)는 배치 A 사용처 합계(약 46분)의 약 12%이고 소비형 업적 보상은 사용 금액의 3% 이하라 사용처 가치를 줄이지 않는다(`m2-achievements.md` §7.3·§7.4). 시간 이벤트의 확률 효과(+5%p, `BONUS_CAP` 안)는 1,261회 기준 5분 창 최대 4.3%·런 기대 ≤1.2%(`m2-events.md` §7).

## I. 인수 조건 (Given/When/Then)
1. **종류 변경 가격**: Given `S.best=13` / `15` / `20`, When `traitRekindCost(S)`, Then 각각 `214,100` / `732,600` / `15,877,000`(= round100(80×2,676 / 9,158 / 198,462)).
2. **등급 올리기 가격**: Given `S.best=13` / `15` / `20`, When `traitTierUpCost(S, 1)`, Then `535,200` / `1,831,600` / `39,692,400`. When `traitTierUpCost(S, 2)`, Then `1,338,000` / `4,579,000` / `99,231,000`. When `t`가 1·2가 아니면 Then `null`.
3. **기념비 가격**: When `monumentCost(13)`, `monumentCost(15)`, `monumentCost(20)`, Then `401,400` / `1,373,700` / `29,769,300`. 13..20 합계 = `64,320,100`.
4. **기념비 구매 규칙**: C.3의 M1~M5(성공, 이미 보유, 미도달, 골드 부족, 잘못된 L)가 각각 정해진 결과와 `reason`을 내고, 실패 시 골드·`monuments`·`stats.sinkGold`가 변하지 않는다.
5. **저장 정규화(기념비)**: Given 저장에 `monuments`가 없음 / 배열이 아님 / 길이 3 / 길이 10 / 값 `[2,0,"a",null,...]`, When 로드, Then 항상 길이 8의 0·1 배열이며(없음·비배열은 전부 0, 짧으면 0으로 채움, 길면 8칸으로 자름, truthy → 1), 보유 칸 L이 `S.best`보다 커도 그대로 둔다.
6. **저장 정규화(통계)**: Given 저장에 `stats.sinkGold`·`stats.traitRolls`가 없음 / 음수 / 문자열, When 로드, Then 0 이상 정수이며 기본 0. Given 옛 저장(해당 필드 없음), When 로드, Then 새 필드가 기본값으로 채워지고 다른 필드는 그대로, 저장 `v`는 2다. 저장 후 다시 불러와도 같은 상태.
7. **기존 수입·가격 회귀**: Given M1 수치(huntReward 13→2,676, 15→9,158, 20→198,462; `autoReward(15)`=1,432; `boosterPrice(15)`=366,300 등), When M2 코드 적용 후 같은 입력으로 호출, Then 출력이 이전과 같다(`huntReward`·`autoReward`·`boosterPrice`·`cost`·`sell`·`SLOT_EXPAND_COST`·`UP_COST_BASE`·`PRICE` 불변).
8. **페이스 보호**: Given 임의의 `S`, When `traitRekindCost`·`traitTierUpCost`·`buyMonument`를 실행(성공 포함), Then `chances()` 출력, 게이지, 숙련 기록, `BONUS_CAP` 값이 실행 전과 같다.
9. **해금**: Given `S.best=12`, When 종류 변경·등급 올리기를 시도, Then 거부(`locked`, 사유 이름은 `m2-traits.md`). Given `S.best=13`, Then 허용.
10. **배치 B 인수 조건 위치**: F12 업적·일일 과제의 AC는 `m2-achievements.md` §16, F13 시간 이벤트의 AC는 `m2-events.md` §14에 있다. 항목 7(기존 수입·가격 회귀)·8(페이스 보호)은 F12의 `claim*`·`refreshDaily`·`syncAchievements`와 F13의 `advanceEvents`·이벤트 효과도 같은 입력에서 `huntReward`·`autoReward`·`boosterPrice`·`cost`·`sell`·가격 상수를 바꾸지 않고, 사용처 실행이 `chances()`·게이지·숙련·`BONUS_CAP` 값을 바꾸지 않는다는 뜻으로 확장해 읽는다(이벤트 비활성 시 `chances()` 출력은 M1과 같다).
