# M1 납품 의뢰 (F4)

> 저장 필드: `quests.list[]`, `quests.readyAt[]`, `stats.delivered` (`m1-storage.md` §3). 의뢰는 **보관함(F5)의 검을 소모**해 완료한다.

## 1. 결정 요약
| 항목 | 결정 |
| --- | --- |
| 해금 | `best ≥ QUEST_UNLOCK_BEST`(3) 달성 시 "의뢰" 탭 활성 |
| 동시 의뢰 수 | `QUEST_SLOTS`=3, 슬롯마다 난이도 고정: 0=쉬움, 1=보통, 2=어려움 |
| 요구 조건 | **정확히 그 단계(lv)의 검 1자루**(더 높은 검은 불가). 추가 조건 없음(단순화) |
| 납품 시 | 검 **소멸**(판매와 동일하게 칸이 비워짐) |
| 만료 | 없음(압박 없음, 오프라인 처리 단순) |
| 갱신 | (a) 납품 후 해당 슬롯은 `QUEST_COOLDOWN_SEC`(300초) 뒤 새 의뢰 생성(실시간, 오프라인 경과도 포함) (b) 슬롯별 골드 새로고침 `QUEST_REROLL_COST`. **의뢰 갱신권 아이템은 만들지 않음**(골드 새로고침으로 대체, consumables 참조) |
| 퀘스트 토큰 | 없음. 의뢰 보상은 골드/소모품/파편만 사용 |

## 2. 요구 단계 생성
`best`는 역대 최고 단계. 슬롯 난이도별:
```
lv_easy   = max(2, floor(best / 2))                     // QUEST_LV_EASY_DIV = 2
lv_normal = max(3, best - QUEST_LV_NORMAL_OFFSET)       // OFFSET = 3
lv_hard   = max(4, best - QUEST_LV_HARD_OFFSET)         // OFFSET = 1
모두 min(lv, MAX) 로 자름
```
- 같은 시점의 3개 의뢰가 같은 단계가 되면(예: best가 작을 때) 뒤 슬롯의 `lv`를 +1(최대 MAX)씩 올려 서로 다르게 한다.
- 생성 시점의 `best`로 고정(이후 `best`가 올라도 의뢰는 그대로).
- 어려움은 "지금 최고 단계 바로 아래 단계 검을 하나 따로 만들어 둬야" 하므로 보관함 사용을 유도(주력 검을 키우다 중간 단계에서 새 검으로 만들어 두는 선택).

## 3. 보상
의뢰 객체는 생성 시 보상을 확정한다.
```
gold = round(sell(lv) * QUEST_GOLD_MULT[tier] / 10) * 10      // 잠정: easy 1.3, normal 1.5, hard 1.8
item = QUEST_ITEM_CHANCE[tier] 확률로 아래 풀에서 균등 추첨 (잠정: easy 50%, normal 80%, hard 100%)
```
| 난이도 | 아이템 풀 (id × 수량) |
| --- | --- |
| 쉬움 | `bless`×2, `keepdown`×1, `shard`×`shardGain(max(5, lv))` |
| 보통 | `protect`×1, `anvil_1`×1, `keepdown`×1, `sure`×1 |
| 어려움 | `protect`×2, `anvil_2`×1, `sure`×2, `booster`×1, `seal`×1 |
- 보유 상한 때문에 지급할 수 없으면(스택 99, 모루 `ANVIL_OWN_MAX`) 해당 품목의 `SHARD_COST`만큼 파편으로 대체 지급하고 로그에 표기. (`booster`/`seal`은 파편 가치 없음 → 상한 시 `SHARD_COST.protect` 파편으로 대체)
- 감정 인장(`seal`) 토글 ON이면 **골드 부분만** `SEAL_MULT`(1.3)배(아이템 보상은 불변).

### 판매보다 이득인 이유
같은 검 판매 대비 골드 130~180% + 아이템. 단점: 정확히 그 단계 검이어야 하고 슬롯이 대기(쿨다운) 상태가 되며 갱신에 시간이 걸림 → 납품 대상 검을 일부러 보관해야 하는 "보관함 판단"이 생긴다. `QUEST_GOLD_MULT`는 밸런스 담당이 사냥 수입(F1)과 비교해 확정.

## 4. 의뢰 객체 (저장 형태)
```json
{ "id": 7, "tier": "normal", "lv": 9, "gold": 11400, "item": { "id": "protect", "n": 1 } }
```
`item`은 null 가능. `quests.nextId`가 필요하면 `quests` 객체에 추가(기본 1).

## 5. UI
- 의뢰 탭: 카드 3장. 카드 = 난이도 뱃지, "요구: +9 {검 이름}", 보상(골드 + 아이템 아이콘), 버튼 [납품] [새로고침 N G].
- [납품]은 보관함(활성 포함)에 `lv`가 같은 검이 있을 때만 활성. 여러 자루면 선택 팝업 없이 **활성이 아닌 검을 우선, 같은 조건이면 `id`가 작은 검**을 소모(주력 검 오사용 방지). 활성 검뿐이면 확인 대화(2회 클릭 방식 재사용).
- 조건 미충족: 버튼 비활성 + "보유 검 없음 · +9 필요" 문구. 현재 보유 중 가장 가까운 단계를 부제로: "가진 검: +7, +12".
- 쿨다운 슬롯: "다음 의뢰까지 mm:ss" (카운트다운은 타임스탬프 차이로 렌더).
- 보관함 칸 카드에는 납품 가능한 검에 `📦` 뱃지.
- 헤더 의뢰 탭에 "납품 가능" 개수 점.

## 6. 오프라인/시간
- `readyAt`은 epoch ms. 로드·복귀(visibilitychange) 시 `now ≥ readyAt`이고 슬롯이 null이면 즉시 생성. 오프라인 시간만큼 쿨다운이 진행된 것으로 취급.
- 의뢰는 만료가 없으므로 오프라인 중 소실 없음.
- 시계가 거꾸로 간 경우(`readyAt - now > QUEST_COOLDOWN_SEC*1000`)에는 `readyAt = now + QUEST_COOLDOWN_SEC*1000`로 보정.
- 마이그레이션 직후(v1→v2) 해금 조건(`best ≥ 3`)을 만족하면 3개 의뢰를 즉시 생성.

## 열린 질문 (사용자 확인 필요)
1. 요구를 "정확히 그 단계"(권장) vs "그 단계 이상". 이상이면 주력 검 납품이 쉬워져 보관함 가치가 하락.
2. 의뢰 갱신권을 소모품에서 제외(권장)하고 골드 새로고침으로 대체해도 되는지.

## 수용 기준 (Acceptance criteria)
1. Given `best=2`일 때 / Then 의뢰 탭은 잠금 표시이고 의뢰가 생성되지 않는다. `best=3` 달성 즉시 3개 의뢰가 생성된다.
2. Given `best=10` / Then 슬롯별 `lv`는 쉬움 5, 보통 7, 어려움 9. 같은 `lv` 중복은 없다.
3. Given 의뢰 `lv=7`이고 보관함에 +7 검(비활성)이 있을 때 / When [납품] / Then 그 검이 사라지고 `gold += quest.gold`, 아이템이 `inv`에 추가, `stats.delivered`+1, 슬롯은 null이 되고 `readyAt=now+300초`.
4. Given 보관함에 +7이 없고 +6, +8만 있을 때 / Then [납품]은 비활성이며 필요 단계가 표시된다.
5. Given +7이 활성 검 1개와 비활성 검 1개 모두 있을 때 / When 납품 / Then 비활성 검이 소모된다.
6. Given 납품할 검이 활성 검이고 다른 검이 없을 때 / Then 확인 후 납품되면 무료 +0이 지급되고 활성이 된다.
7. Given 슬롯 쿨다운 중 / When 새로고침 버튼을 누르면 / Then 불가(생성 대기 상태). 의뢰가 있는 슬롯에서 골드 ≥ `QUEST_REROLL_COST`일 때 새로고침하면 골드가 줄고 즉시 새 의뢰(현재 `best` 기준)로 교체된다.
8. Given 쿨다운이 남은 상태로 앱을 닫고 5분 뒤 다시 열면 / Then 해당 슬롯에 의뢰가 새로 생성되어 있다.
9. Given `seal` 토글 ON으로 납품 / Then 골드 보상만 1.3배이고 `inv.seal`-1, 토글 해제.
10. Given 모루 보유가 `ANVIL_OWN_MAX`일 때 모루 보상 납품 / Then 모루 대신 파편이 지급되고 로그에 표기된다.
11. Given 같은 `best`와 슬롯에서 gold = `round(sell(lv)*mult/10)*10`이며 `sell(lv)`보다 항상 크다.
