## 1. 결론
1. 현행 체감이 긴 이유는 +15 이상의 확률 자체보다 **"후반 실패 → 하락 → +10~14 오르내림 → 파괴 → +0부터 재등반"** 고리다. 소모품을 여유 있을 때만 사는 일반 플레이(P-Realistic)는 시도의 97%, 파괴의 93%가 +15 아래에서 나온다(§2.4).
2. 그래서 검 단위가 아니라 **계정 단위**로 쌓여 파괴를 넘어 유지되는 장치가 필요하다. 검 단위 게이지는 효과가 없다(Realistic 16.6h, 현행 17.0h).
3. 추천: **A 천장 게이지(계정·단계별 하드 천장) + C 대장장이 숙련(+10 이상 누적 시도 → +10 이상 성공률 +2~10%p, 상한 밖)**. A는 "운이 나빠도 정해진 횟수 안에 진행"을 보장하고, C는 많이 고생한 플레이어일수록 크게 돕는 따라잡기 장치라 p90 꼬리를 자른다. Heavy는 조금 빨라지고(0.63h → 0.44h), Realistic은 17.0h → 4.5h(p90 56.6h → 8.6h).

### 2.5 0.62h가 체감과 다른 이유
1. **정책**: 0.62h는 하락 방지·보호·확정권·축복을 이득이 되는 모든 곳에 완벽하게 쓰는 플레이다. 여유 골드로만 사는 일반 플레이는 +20까지 **27배(17h, 하루 30분이면 35일)**, p90은 57h(114일)다.
2. **고리**: +15 이상 시도 수는 Heavy 166회, Realistic 239회로 비슷하다. 차이는 후반 실패 → 하락 → 하락 방지 없는 +10~14 오르내림 → 파괴(Realistic +20까지 345회) → **+0부터 재등반**에서 난다.
3. **골드 대기**: 모든 프로필에서 접속 시간의 70~90%가 사냥이다. 파괴되면 수입 기준 검(`topLv`)이 +0이 되어, 재등반 구간은 사냥 1회가 시도 비용의 26%(+10)밖에 안 된다.
4. **꼬리**: p90/중앙값이 2.9~3.3으로 길고, 소모품 없이는 +20이 사실상 막혀 있다(150h 안 2%). 구 문서의 "실제는 2~3배" 추정은 Heavy 정책 안에서의 사냥 효율만 본 값이었다.

## 4. 후보별 검토 (시스템 기획 초안 요약 + 시뮬 결과)
공통: 후반 = +15~+19, 배열 인덱스 `l-15`. 신규 저장 필드는 v2에 **추가 필드 + 기본값 병합**(버전 유지, 마이그레이션 없음). 테스트 페이지(`forceSuccess`)는 별도 저장이라 카운터도 별도.
초안 관찰 확인: +15 이상에서는 실패 = 하락이고 하락 뒤 재성공에서 `pity`가 0이 되므로, `pity`는 보호로 막은 파괴로만 쌓인다(F 단독이 약한 이유).

### A. 천장 게이지 (계정·단계별 하드 천장) — 채택(조정값)
- 규칙: `gauge[l]`(계정 공유). +15~19 단계 `l`에서 성공이 아니면(실패·하락·파괴·보호로 막은 파괴) +1, 최대 `GAUGE_N`. `gauge[l] ≥ GAUGE_N`이면 그 단계 다음 시도는 **확정 성공**(성공 100 / 파괴 0, 상한·천장·보정 우회, `cost(l)`은 냄). 그 단계 성공(자연·확정) 시 `gauge[l]=0`. 파괴·하락·판매·검 전환은 게이지에 영향 없음. 가득 차면 트레이 토글은 `gaugeFull` 사유로 잠김(소모품 낭비 방지).
- 결과: 초안 N=[5,7,10,14,20]은 Realistic 13.6h로 약하다. N=[4,5,6,8,10]이면 Heavy 0.49 / Realistic 10.0 / Light 도달 7%. N=[2,3,4,5,6](`A_hard`)이면 Realistic 5.03h까지 가지만 Heavy가 0.29h로 반 토막 나고 +20의 28%가 확정이라 "사건"이 사라진다. 게이지만으로 Realistic을 줄이려면 후반을 쉽게 만드는 수밖에 없어 C와 묶는다.
- 검 단위로 하면(`A_sword`) 효과 없음: Realistic 16.6h. 게이지가 차기 전에 검이 파괴되어 게이지도 함께 사라지기 때문.
- 악용: 단계별이라 싼 단계로 높은 단계 게이지를 못 채운다. 같은 단계 희생 검은 비용이 같아 공짜 이득이 없다. 가득 찬 게이지는 파괴·판매 후에도 남아 다음 방문에 1회 확정(의도, 1회분).

### B. 단계 숙련 — 보류
- 규칙: `mastery[l]` = 단계 `l` 누적 시도. `floor(mastery/PER_PT[l-15])`%p(최대 10), 상한 밖.
- 결과: 초안 Realistic 13.6 / 32.5, 빠르게 한 값(`B_fast`, [4,5,6,8,10])도 10.8 / 25.5. Realistic의 문제는 +15 아래 고리라 +15~19 시도만 세는 B는 고생한 정도를 잘 못 잡는다. C와 성격이 같고 UI가 5행 필요 → C로 대체.

### C. 대장장이 숙련 — 채택(조정값, 보너스 +10부터)
- 규칙: `smithTries` = +10 이상에서 한 시도 수(결과 무관, 확정 성공 포함). 등급 = 넘은 임계값 수(`SMITH_TRIES`). +`SMITH_BONUS_FROM` 이상에서 `SMITH_BONUS[등급]`%p, **상한 밖**, 천장 90 적용.
- 결과: 초안(임계 300~1만, 최대 +5)은 Realistic 13.2 / 34.6, Heavy 0.62 / 1.55로 약하다. 조정값(임계 100~2,000, 최대 +10, +15부터)만으로 Realistic 6.63 / 16.0. 상한 안에 넣으면(`C_inCap`) 축복·모루를 쓰는 순간 효과가 사라져 Realistic 16.5h로 무의미.
- 특징: Heavy는 +20까지 +10 이상 시도가 약 180회라 1등급(+2)에 그치고, Realistic은 수백~수천 회라 빨리 최고 등급에 간다. **고생한 만큼 돕는 따라잡기**라 p90이 크게 준다.

### D. 검 합성 — 비추천 (M2 후보)
- 규칙: 같은 단계 `l`(10~18) 두 자루 + `cost(l)` → 확률 `FUSE_RATE`(90~30%)로 `l+1`, 실패 시 재료 1자루 소멸. +20은 강화로만.
- 결과: Realistic 2.66h로 가장 크게 줄지만, 이유는 합성이 아니라 **보관함에 세워 둔 고단계 검이 `topLv` 수입을 유지**하는 효과다(사냥 비중 81% → 24%). Heavy는 오히려 0.84h, Light는 +19→+20을 굴려야 해서 도달 10%. 새 행동·UI·실패 규칙이 필요하고 수입 인플레·의뢰 저가 충족 위험이 크다.

### E. 상급 확정권 `sure2` — 비추천
- 규칙: +15~19 확정 성공권, 단계별 1~3장, 상점 고정가.
- 결과: 초안 4만G는 Heavy가 **+20까지 34회, 0.12h**. 수동 사냥 1회가 +19에서 10.7만G(+18 5.8만G)라 고정가는 몇 초 사냥이면 된다. 가격을 단계 기대비용의 1.5배로 올리면 Heavy는 안 사고 Realistic은 여유 골드를 보호권 대신 확정권에 써서 오히려 느려진다(17.8h). M0 사냥식(`m1-balance` §8 결정 3)이 바뀌기 전에는 가격으로 균형을 잡을 수 없다. (초안 단계에서 상한 밖 +%p 아이템 "대축복"(E1)은 F의 상한 상향과 효과가 같아 컷.)

### F. 실패 보정·상한 변경 — 단독 비추천, 상한 변경 불필요
- 규칙(초안): 밴드3 `PITY_STEP` 2→3, `PITY_MAX` 10→15, `BONUS_CAP[3]` 14→18.
- 결과: Heavy 0.53 / 1.37, Realistic 14.0 / 44.1(p90/중앙값 3.1로 꼬리가 그대로). 상한 20 + pity 3/15(`F_cap20`)도 Realistic 12.5 / 39.0. +15 이상에서 `pity`가 거의 쌓이지 않아 효과가 작다. A와 묶은 A+F(8.04 / 21.4)도 A+C보다 약하다. 추천 패키지는 C를 상한 밖에 두므로 상한을 바꿀 이유가 없다.

## 5. 추천 패키지: A 천장 게이지 + C 대장장이 숙련
### 5.1 규칙
```
guaranteed = (opts.sure AND l < 10) OR (15 <= l <= 19 AND gauge[l-15] >= GAUGE_N[l-15])  // succ 100, dest 0
raw    = bless + anvil + pity                 // 기존
bonus  = min(raw, BONUS_CAP[band])            // 기존 [20,20,14,14] 그대로
smith  = l >= SMITH_BONUS_FROM ? SMITH_BONUS[smithLv] : 0     // 상한 밖
succ   = min(base + bonus + smith, max(base, SUCC_CEIL))
dest   = max(0, min(DESTROY[l], 100 - succ))  // 기존
smithLv = count(t in SMITH_TRIES where smithTries >= t)        // 0..5
시도 후: l >= SMITH_COUNT_FROM 이면 smithTries += 1
        15 <= l <= 19: 성공이면 gauge[l-15] = 0, 아니면 gauge[l-15] = min(GAUGE_N, gauge+1)
```
- `chances(sword, opts)`는 `S`를 모르므로 호출 측이 `opts.gaugeFull`, `opts.smith`를 넣는다(순수 로직 유지).

### 5.2 상수
| 이름 | 값 | 의미 |
| --- | --- | --- |
| `GAUGE_FROM` / `GAUGE_TO` | 15 / 19 | 게이지 대상 단계 |
| `GAUGE_N` | [4, 5, 6, 8, 10] | +15~+19에서 허용 실패 수. 다 차면 다음 시도 확정(최악 N+1회) |
| `SMITH_COUNT_FROM` | 10 | 이 단계 이상 시도 1회 = 숙련 1 |
| `SMITH_TRIES` | [100, 250, 500, 1000, 2000] | 숙련 1~5등급 임계값 |
| `SMITH_BONUS` | [0, 2, 4, 6, 8, 10] | 등급별 성공률 %p (상한 밖) |
| `SMITH_BONUS_FROM` | 10 | 보너스 적용 시작 단계 (대안 15, 질문 2) |
| `BONUS_CAP` / `PITY_STEP` / `PITY_MAX` / `SUCC_CEIL` | 변경 없음 | [20,20,14,14] / [1,1,2,2] / [5,6,8,10] / 90 |

### 5.3 결과 (`candidates.js AC10`, 2,000/2,000/300명)
| 프로필 | +15 접속 h | +18 접속 h | +20 시도 중앙값 / p90 | +20 골드 | +20 접속 h 중앙값 / p90 | +20 일수 중앙값 / p90 | +20 파괴 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| P-Heavy | 0.11 / 0.19 | 0.19 / 0.35 | 234 / 475 | 409만 | 0.44 / 0.72 | 1 / 2 | 4 |
| P-Realistic | 0.51 / 1.07 | 2.01 / 4.01 | 1,857 / 3,743 | 550만 | **4.51 / 8.56** | 10 / 18 | 90 |
| P-Light | 0.64 / 1.56 | 7.07 / 11.5 | 2.6만 / 6.9만 | 4,231만 | 41.1 / 106 (도달 99%) | 83 / 212 | 1,374 |
- +15 도달 시간은 현행과 같다(숙련이 아직 쌓이지 않음). 처음 하는 중반 경험은 바뀌지 않는다.

### 5.4 상호작용·점검
- **천장 90%**: 패키지 최대 성공률은 +10에서 45 + 14 + 10 = 69%, +15 이상은 최대 44%. 천장에 닿지 않는다(`selfcheck.js`).
- **상한**: 숙련은 상한 밖이라 축복·미스릴로 이미 상한(14)인 Heavy도 받는다. UI 분해줄에 상한과 따로 `숙련 +N`으로 보여 준다.
- **+20은 여전히 사건인가**: +19 성공률은 Heavy 19% → 숙련 최고 시 29%, +19 시도 중앙값 3~4회, +20을 확정으로 얻는 비율 5~17%. 게이지 +19 천장(10회 실패)은 운이 매우 나쁠 때만 작동한다.
- **보호권·하락 방지**: 확정 시도는 파괴 0이라 보호권이 소모되지 않는다. 확정권(`sure`, +9 이하)과 범위가 겹치지 않는다.
- **악용**
  - 게이지 싼 시도 파밍: 단계별이라 불가. 같은 단계 희생 검은 비용이 같다.
  - 파괴된 검의 게이지: 계정 단위로 남는다(의도). 이게 꼬리를 자르는 핵심이다.
  - 숙련 의도적 파밍: +18 검을 세워 두고 +10~14만 반복하면 최고 등급까지 **접속 1.40h**(`probe-smith-farm.js`). Heavy의 +20 전체(0.44h)보다 길어 첫 +20에서는 이득이 없다. 보너스 최대 +10%p로 묶여 있다.
  - 보관함·`topLv` 수입: 패키지는 검 수를 늘리지 않아 영향 없음.
- **저장**: `gauge: int[5]`(기본 0, 로드 시 길이 5 보정, 0..`GAUGE_N[i]` clamp), `smithTries: int`(기본 0, 0 이상 안전 정수 clamp). v2 유지, 기존 저장은 0으로 시작.
- **UI**(초안 따름): +15 이상에서 확률 아래 `천장 3/6` 막대, 가득 차면 `확정!` 배지와 성공률 100%. 기록 탭·자원바에 `대장장이 Lv.2 · +4%p (312/500)`, 등급 상승 토스트 1회. 트레이 분해줄에 `숙련 +4`.

### 5.5 수용 기준
1. Given `gauge[15]=3`(N=4), +15 실패 / Then `gauge[15]=4`, 다음 +15 시도 chances = `{succ:100, dest:0, fail:0}`.
2. Given 게이지 가득, 축복·모루 ON / Then 토글은 `gaugeFull` 사유로 잠기고 `inv.bless`·모루 내구도가 줄지 않으며 골드는 `cost(l)`만 줄어든다.
3. Given +16에서 성공(자연 또는 확정) / Then `gauge[16]=0`, 다른 단계 게이지는 그대로.
4. Given +17에서 보호 없이 파괴 / Then 검은 사라지고 `gauge[17]`은 +1. 저장·새로고침 후 복원된다.
5. Given +14 이하 시도 / Then 게이지 변화 없음.
6. Given +9 시도 / Then `smithTries` 그대로. +10 이상 시도(확정 포함) / Then +1.
7. Given `smithTries=500`(3등급) / Then +10 이상 시도에 +6%p. +15, 축복+미스릴, pity 0이면 succ = 20 + 14 + 6 = 40.
8. Given `smithTries=2000`, +10, 축복+미스릴+pity 최대 / Then succ = 45 + 14 + 10 = 69 (천장 90 미만). 어떤 입력에서도 `succ+dest+fail=100`, `dest ≥ 0`.
9. Given `gauge`·`smithTries`가 없는 기존 v2 저장 / Then 로드 시 0으로 채워지고 오류가 없다. 범위를 벗어난 값은 clamp된다.
10. 밸런스: `node tools/sim-late/candidates.js AC10` (seed 20261118)에서 §3 목표를 모두 만족하고, `node tools/sim-late/selfcheck.js`가 통과한다.

## 6. M2 환생 메모
- 숙련 유지 + 게이지 리셋으로 두 번째 판을 돌리면(`AC10_rebirth`): Heavy 0.20 / 0.39h, Realistic **1.53 / 4.21h**(첫 판 4.51 / 8.56), Light 41.7h(숙련이 첫 판에서도 일찍 최고가 되어 차이 없음).
- 즉 숙련을 유지하면 그 자체가 약 3배 빠른 환생 보상이 된다. M2에서 기본 성공률 같은 환생 보상을 더한다면 숙련과 합산 상한을 함께 설계해야 한다.
- 게이지는 "지금 판의 불운 누적"이라 환생 시 리셋이 자연스럽다.
