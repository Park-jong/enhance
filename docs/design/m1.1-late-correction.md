## 2. 천장 게이지 규칙
- 대상 단계 `l = GAUGE_FROM..GAUGE_TO`(15..19). 인덱스 `i = l - GAUGE_FROM`. 값 `S.gauge[i]` (0..`GAUGE_N[i]`).
- **증가**: 시작 단계가 l인 시도의 결과가 성공이 아니면 +1. 실패(유지/하락), 하락, 파괴, 보호권이 막은 파괴 모두 포함. 성공이면 `S.gauge[i]=0`.
- 참고: 하락 방지(`keepdown`)는 `KEEPDOWN_MAX_LV`(15) 이상에서 쓸 수 없으므로 +15~+19의 게이지 증가 사유에 "하락 방지로 유지된 실패"는 없다.
- **가득 참**: `gauge[i] >= GAUGE_N[i]`이면 활성 검이 +l일 때 `gaugeFull=true`. 이 시도는 확정 성공이며 성공 후 `gauge[i]=0`.
- **확정 시도의 효과**: 성공률 100, 파괴 0, 실패 0. 강화 비용 `cost(l)`은 정상 지불. 천장(`SUCC_CEIL`)·`BONUS_CAP`·숙련 계산을 모두 건너뜀.
- **토글 잠금**: 확정 시도에서는 `bless`/`anvil`/`protect`/`keepdown`(및 `sure`) 토글이 비활성이며 툴팁 사유 `gaugeFull`("천장 확정: 소모품이 필요 없음"). 소모품·모루 내구도·보호 횟수는 소모하지 않는다. 토글의 저장된 `use` 값은 바꾸지 않아도 되나, 시도 시 소모하지 않아야 한다.
- **계정 공통**: 검 개체가 아니라 계정에 붙는다. 검을 파괴/판매/전환해도 유지(검마다 `pity`와는 다름). 이 때문에 파괴돼도 다음 검의 +l 시도에서 이어진다.
- **게이지 증가 기준 단계 = 시도 시작 단계**: 하락(+16→+15)으로 단계가 바뀌어도 +16 게이지에 더한다.
- 다른 규칙과 겹침: 실패 보정 `pity`는 기존대로(실패 +1, 성공 0). 확정 성공도 성공이므로 `pity=0`. `sure` 확정 강화권은 `l<SURE_MAX_TARGET(10)`에서만 유효하므로 +15~19와 겹치지 않는다.
- +14 이하에는 게이지가 없다.

## 3. 성공 숙련(C') 규칙
### 3.1 무엇을 성공으로 세는가
- `mastery[i]`(i = l - 15, l=15..19) = **단계 l에서 다음 단계로 올린 성공 횟수**(시작 단계 기준).
- 센다: 자연 성공, **천장 확정 성공**(사용자 질문 2, 아래 §10에서 "센다"로 정하고 확인 요청).
- 안 센다: 실패/하락/파괴, +14 이하의 성공, `sure` 확정 강화권, 의뢰 보상, `test.html`의 강제 성공.
- 저장 상한 `MASTERY_REC_MAX[i] = ceil(MASTERY_MAX[i] / MASTERY_STEP[i])`: `[4,4,4,3,2]`. 이를 넘는 성공은 기록을 더 올리지 않는다(보너스는 이미 최대).
- 참고: +19의 숙련 기록은 +20에 도달하는 그 시도로 얻는다. M1의 끝이므로 M2 환생 이후에만 의미가 있다.

### 3.2 보너스 식과 위치
```
mBonus(l) = min(MASTERY_MAX[l-15], mastery[l-15] * MASTERY_STEP[l-15])   // %p, l=15..19. 그 외 0
```
- 단계별 독립이라 낮은 단계의 반복이 높은 단계를 올려 주지 않는다.
- **`BONUS_CAP` 밖**: 축복+모루+pity의 raw/상한 계산에 넣지 않는다. 합산은 상한 이후에 더한다.
- **`SUCC_CEIL`은 적용**: `succ = min(base + bonus + mBonus, max(base, SUCC_CEIL))`. 단 숙련으로는 90에 닿지 않는다(§4 최대표).
- 파괴율 식은 기존 그대로: `dest = max(0, min(DESTROY[l], 100 - succ))`. 숙련이 파괴율을 낮추지 않는다.

### 3.3 `chances` 전체 순서 (의사코드)
```
function chances(sword, opts):   // opts: {bless, anvilGrade, sure, gaugeFull, mastery}
  l = sword.lv
  if l >= MAX: return {succ:0, dest:0, fail:0}
  if opts.sure AND l < SURE_MAX_TARGET: return {succ:100, dest:0, fail:0}       // 1) sure
  if opts.gaugeFull AND GAUGE_FROM <= l <= GAUGE_TO:
      return {succ:100, dest:0, fail:0, gaugeFull:true}                        // 2) 천장 확정
  base   = RATE[l]
  raw    = bBless + bAnvil + bPity;  bonus = min(raw, BONUS_CAP[band])          // 3) 기존
  mBonus = (MASTERY_FROM <= l <= MASTERY_TO) ? min(MASTERY_MAX[i], (opts.mastery||0)*MASTERY_STEP[i]) : 0
  succ   = min(base + bonus + mBonus, max(base, SUCC_CEIL))                     // 4)
  dest   = max(0, min(DESTROY[l], 100 - succ));  fail = 100 - succ - dest       // 5)
```
- `opts.mastery`는 호출자가 `S.mastery[l-15]`(횟수)로 주입. `opts.gaugeFull`은 `S.gauge[l-15] >= GAUGE_N[l-15]`.
- 호출 후 `attemptEnhance`가 결과로 `S.gauge`/`S.mastery`를 갱신(게이지는 시도 시작 단계 기준).

## 4. 상수
| 이름 | 의미 | 값 |
| --- | --- | --- |
| `GAUGE_FROM` / `GAUGE_TO` | 게이지 대상 단계 | 15 / 19 |
| `GAUGE_N[i]` | 가득 차는 비성공 횟수(i=l-15) | [4, 5, 6, 8, 10] |
| `MASTERY_FROM` / `MASTERY_TO` | 숙련 대상 단계 | 15 / 19 |
| `MASTERY_STEP[i]` | 성공 1회당 %p | [3, 3, 3, 4, 5] |
| `MASTERY_MAX[i]` | 숙련 최대 %p | [12, 12, 12, 12, 10] |
| `MASTERY_REC_MAX[i]` | 저장 기록 상한 = `ceil(MAX/STEP)` | [4, 4, 4, 3, 2] |
| `BONUS_CAP` `PITY_STEP` `PITY_MAX` `SUCC_CEIL` | 변경 없음 | [20,20,14,14] / [1,1,2,2] / [5,6,8,10] / 90 |

최대 성공률(축복 10 + 미스릴 모루 4 + 숙련 최대, pity 0): +15 **46**, +16 **41**, +17 **36**, +18 **33**, +19 **29**. 90에 닿지 않는다. 보너스 합계(raw)는 `BONUS_CAP`(14)에 걸리므로 pity를 최대로 쌓아도 같은 값이다(+15: raw 24→14, 20+14+12 = 46, §12 수용 기준 9). 즉 "pity 최대 56"은 상한 때문에 불가능하다.

## 6. 손계산표 (시뮬레이션 아님)
단계에 한 번 들어와 성공할 때까지의 기대 시도 수 = Σ(k=0..N)(1-p)^k. **하락 후 다시 올라오는 시도는 별도(추가)로 포함하지 않았다.**
열: 소모품 없음(현행 / A만) · 축복+미스릴 p+14(현행 / A) · 거기에 숙련 최대(현행 / A).

| 단계 (p, N) | 소모품 없음 | 축복+미스릴 | + 숙련 최대 |
| --- | --- | --- | --- |
| +15 (p20, N4) | 5.0 / 3.4 | 2.9 / 2.6 (p34) | 2.2 / 2.1 (p46) |
| +16 (p15, N5) | 6.7 / 4.2 | 3.4 / 3.0 | 2.4 / 2.3 |
| +17 (p10, N6) | 10.0 / 5.2 | 4.2 / 3.6 | 2.8 / 2.7 |
| +18 (p7, N8) | 14.3 / 6.9 | 4.8 / 4.2 | 3.0 / 2.9 |
| +19 (p5, N10) | 20.0 / 8.6 | 5.3 / 4.7 | 3.4 / 3.4 |

읽는 법: **숙련은 소모품을 덜 쓰는 플레이어일수록 더 도움이 되는 따라잡기 장치**이고, **A는 긴 꼬리(운 나쁜 구간)를 자른다**. 소모품을 다 쓰고 숙련도 최대면 A의 추가 효과는 거의 없다.

### 6.1 목표 판단 (솔직하게)
1. **수치는 시뮬레이션으로 검증하지 않았다.** 제안서의 자체 시뮬레이션에서 A 단독은 Realistic +20 약 10h(현행 17h), A + 횟수 기반 C(+15 시작)는 약 5.5h였고 Light는 53%만 +20에 도달했다. C'는 비슷하거나 약할 것으로 예상한다. **Realistic 대략 5~8h는 추정이지 측정이 아니다.**
2. **P-Light(소모품 없음)는 +10~+14 구간에서 시간을 잃는다.** 따라서 +15부터 시작하는 A+C'만으로는 제안서의 Light 목표(150h 안에 +20 도달 ≥ 90%)를 아마 못 맞춘다. 이 방향 안의 수치 조정으로는 고칠 수 없다. 성공 기록 규칙을 +10~+14까지 내리는 것(예: STEP 1~2, 최대 6%p)만이 해법이다(§10 질문 1).
3. Heavy는 숙련 최대에서 +20 중앙값이 0.35h 아래로 내려갈 수 있다. 그렇다면 STEP을 줄인다.

## 7. 튜닝표 (증상 → 손잡이, 플레이테스트로 판단)
| 증상 | 손잡이 |
| --- | --- |
| +20까지 너무 오래 걸림 | `GAUGE_N`을 줄임(예 [3,4,5,6,8]) 또는 `MASTERY_STEP`+1 |
| Heavy가 너무 빠름 | `MASTERY_STEP`/`MASTERY_MAX` 감소 |
| +17~+19에서 숙련 체감이 없음 | +17~+19의 `MASTERY_STEP` 증가 |
| +20 대기가 여전히 지나치게 김 | `GAUGE_N=[2,3,4,5,6]`이면 제안서 기준으로 +20 약 28%가 확정 성공(과함 주의) |
| Light가 +20까지 못 감 | 이 방향을 벗어남: +10~+14에도 성공 기록(STEP 1~2, 최대 6%p) |
- `GAUGE_N`·`MASTERY_*`는 `js/constants.js` 배열이라 코드 변경 없이 값만 바꾼다. `MASTERY_REC_MAX`는 STEP/MAX를 바꾸면 `ceil(MAX/STEP)`으로 다시 계산.

## 8. 환생(M2) 메모
- 환생 시 **숙련은 유지, 게이지는 초기화**.
- 숙련이 가득 찬 상태로 2회차에 들어가면 +15부터 +12%p 쉬워진다. 따라서 M2 환생 보상은 숙련과 **합산 상한을 함께 설계**해야 한다(보상이 성공률을 더 올리면 90 천장에 가까워짐).
- 융합(D)은 M2 후보로 이동.

## 9. 악용/상호작용
- **싼 +15 성공 반복(파밍)**: 기록 1회마다 +15에 검이 다시 있어야 한다(최적 플레이 기준 +15까지 약 11만 골드/35회 시도). 단계별 기록은 `REC_MAX`(4)까지다. 전부 채우는 비용은 +20 기대 비용(913만 골드)의 약 5%이므로 얇은 루프가 아니다.
- **게이지**: 쌓으려면 실패가 필요하므로 공짜가 아니다. 단계별이라 싼 단계로 높은 단계를 채울 수 없다.
- **+15↔+16 실패/하락 진동**은 정상 플레이이며 상한으로 제한된다.
- 게이지 확정 성공도 숙련 기록이 되므로 게이지로 숙련을 앞당기는 것은 의도된 상호작용이다.
- `sure`는 +9까지, 게이지는 +15 이상이라 겹치지 않는다.
- 모루/보호/하락 방지는 확정 시도에서 소모되지 않으므로 아끼는 효과가 있다(의도).

## 11. UI
- +15~+19에서 성공 확률 아래 `천장 3/6`(분모는 단계별: +16이면 `/5`). 가득 차면 `확정!` 뱃지, 성공률 100%, 토글 비활성 + 툴팁(`gaugeFull`).
- 분해 줄에 `숙련 +6`을 상한 뱃지/취소선과 **분리**해서 표시. 예: `기본 15% + 축복 10 + 모루 4(상한 14) + 숙련 +6 = 35%`.
- 기록 탭: 5행 `+16 숙련 +6%p (2/4)`. 기록 1회 획득마다 토스트 1번: `+16 숙련! 이후 +16 강화 성공률 +3%p`.
- +14 이하에서는 게이지/숙련 표시를 숨김. 확정 시도는 기존 성공 연출을 그대로 쓴다(전용 아이콘은 콘텐츠 팀 선택 사항).

## 12. 수용 기준 (시뮬레이션 게이트 없음)
1. Given 활성 검 +16, `gauge[1]=0` / When 실패, 하락, 파괴, 보호로 막은 파괴 중 어느 것이든 일어나면 / Then 매번 `gauge[1]`+1. `gauge[1]=5`가 되면 `chances`는 100/0/0.
2. Given `gauge[i]`가 가득 참 / Then bless/anvil/protect/keepdown 토글이 사유 `gaugeFull`로 잠기고, 시도 후 소모품·모루 내구도·보호 횟수가 줄지 않으며 골드는 `cost(l)`만 줄어든다.
